# Drivee Data Buddy

## Ссылка доступа

<https://drivee-data-buddy.streamlit.app/>

Drivee Data Buddy — веб-приложение для self-service аналитики: пользователь задаёт вопрос на естественном языке, приложение интерпретирует интент, строит SQL, валидирует его, выполняет в DuckDB и показывает таблицу + график.

### Разработано командой "404: Имя не найдено", в рамках ГРАНД-ФИНАЛА проекта "Моя профессия ИТ 2025/26"

## Что умеет

- Семантический маршрут: метрики/измерения из `semantic/semantic_layer.json`
- Определение интента с confidence score и неоднозначностями
- Уточняющий UX при низкой уверенности (подтверждение/ручной выбор метрики и разреза)
- LLM-генерация SQL через GitHub Models или DeepSeek (OpenAI-совместимый API)
- Guardrails SQL-безопасности (`SELECT`/`WITH`, запрет DDL/DML, только `incity_orders`, авто-`LIMIT`)
- Загрузка собственного CSV через интерфейс
- Готовые сценарии из `semantic/templates.json`
- Скачивание HTML-отчёта с SQL, таблицей и графиком
- Сохранение отчётов в «Мои отчёты»
- Настройка подписок на рассылку отчётов (ежедневно/еженедельно/ежемесячно)
- Имитация отправки email с превью письма

## Архитектура

- `app.py` — UI, роутинг запроса, выполнение SQL, визуализация, экспорт, управление отчётами и подписками
- `intent_resolver.py` — резолв интента (`metric`, `dimension`, `time_range`, `filters`) + `confidence` + `ambiguities`
- `report_manager.py` — CRUD сохранённых отчётов и подписок, JSON-персистентность, имитация email
- `llm_client.py` — инициализация LLM-клиента (GitHub Models, DeepSeek, Mock), промпт, генерация SQL
- `guardrails.py` — валидация и нормализация SQL
- `semantic/semantic_layer.json` — семантический слой (метрики, измерения, aliases, synonyms, time expressions)
- `semantic/templates.json` — готовые аналитические сценарии
- `data/saved_reports.json` — сохранённые отчёты
- `data/subscriptions.json` — настройки подписок

## Локальный запуск

1. Установите зависимости:

```text
pip install -r requirements.txt
```

2. (Опционально) задайте переменные окружения для LLM в `.env`:

```text
LLM_PROVIDER=github
GITHUB_TOKEN=
GITHUB_MODEL=gpt-4o
DEEPSEEK_API_KEY=
DEEPSEEK_MODEL=deepseek-chat
```

3. Запустите приложение:

```text
streamlit run app.py
```

## Как пользоваться

### 1) Аналитический запрос

- Введите вопрос в чат (например: «Отмены по городам за прошлую неделю»)
- Приложение покажет интерпретацию:
  - метрика
  - разрез
  - период
  - уверенность
- При низкой уверенности можно:
  - подтвердить интерпретацию
  - вручную выбрать метрику/разрез
  - запустить fallback через LLM

### 2) Сохранение отчёта

После успешного выполнения запроса:

- нажмите **«💾 Сохранить отчёт»**
- укажите имя отчёта
- отчёт появится в sidebar в разделе **«Отчёты → Мои отчёты»**

### 3) Подписка на рассылку

Для сохранённого отчёта:

- откройте **«Настроить рассылку»**
- укажите email, периодичность, время
- нажмите **«Подписаться»**
- приложение сохранит подписку и покажет тестовую имитацию отправки + превью письма

## Формат хранения

### `data/saved_reports.json`

Сохраняет:

- `id`, `name`, `query`, `sql`, `created_at`
- `chart_type`, `config`
- `preview` (первые строки результата)
- `columns`

### `data/subscriptions.json`

Сохраняет:

- `id`, `report_id`, `report_name`
- `email`, `frequency`, `send_time`, `created_at`

## Примечания по безопасности SQL

`guardrails.py` проверяет, что запрос:

- не пустой;
- содержит только один statement;
- начинается с `SELECT` или `WITH`;
- не содержит запрещённых операций (`DROP`, `DELETE`, `INSERT`, `UPDATE`, `ALTER`, `CREATE`, `TRUNCATE`, `REPLACE`);
- использует только `incity_orders` (и CTE-алиасы);
- получает `LIMIT 1000`, если лимит не задан.
